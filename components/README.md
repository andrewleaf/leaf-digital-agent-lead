# `components/` — React components

Presentation layer. Components receive data as props or read it from a server action's return value; they do not query the database directly.

Structure defined by [`epic-application-architecture-2026-09-15`](../.devtool/features/epic-application-architecture-2026-09-15.md). UI style guide: shadcn/ui (see [`.cursor/skills/shadcn-ui/SKILL.md`](../.cursor/skills/shadcn-ui/SKILL.md)).

## Directories

| Path | Owns |
|------|------|
| `ui/` | shadcn/ui registry primitives (`button.tsx`, `card.tsx`, `table.tsx`, …). Generated by the shadcn CLI. |
| `layout/` | Application chrome composed once per route group: app shell, sidebar nav, top bar, form section wrapper. |
| `campaigns/` | Campaign-scoped components: intake form, campaign card, intake field groups. |
| `queue/` | Agent workspace components: queue table, draft panel, citation panel, status badge. |
| `shared/` | Cross-feature application components: page header, empty state, loading skeletons. |

## Conventions

- `ui/` is CLI-generated and owned by the registry. Add components with the shadcn CLI rather than hand-writing them. Customise via Tailwind classes and design tokens at the call site; edit a registry file directly only when the change is deliberate and permanent, since it will not survive a re-add.
- Prefer a registry primitive over a new one-off primitive.
- File names are kebab-case; the exported component is PascalCase.

## Import rules

- `campaigns/` and `queue/` may import from `ui/`, `layout/`, and `shared/`.
- `campaigns/` and `queue/` must not import from each other. Promote anything they both need into `shared/`.
- `ui/`, `layout/`, and `shared/` must not import from a feature folder.
- No component imports from `app/`.
